## 二、 STAR法则深度剖析

### Situation (背景)

我参与此项目时，面临的**背景**是：我国新一代通信卫星在设计中引入了更复杂的内部以太网和CAN总线网络，这在提升通信能力的同时，也带来了前所未有的网络安全风险。由于星地链路具有**带宽窄（<1Mbps）、延迟高（数百毫秒至数分钟）、非实时**的特点，不可能将全部总线数据下传至地面进行分析。因此，必须在卫星上（即“边缘侧”）部署一个能够**实时检测**恶意指令注入、DoS攻击等威胁的入侵检测系统（NIDS），以确保卫星的绝对安全。

我们选用的硬件平台是**RK3588**嵌入式开发板，它搭载了算力为6 TOPS的NPU，但整个载荷板的**内存仅为4GB**，且必须在**小于15W**的严格功耗预算下稳定运行。

### Task (任务)

我的核心**任务**是作为AI模型部署工程师，解决从算法到在轨应用“最后一公里”的关键问题。具体包括：
1.  **模型部署**：将算法团队提供的、基于Transformer的PyTorch模型（FP32精度），成功部署到资源极其受限的RK3588平台上。
2.  **性能优化**：必须利用板载NPU进行加速，使单次推理延迟低于20ms，以满足总线网络的实时处理要求。
3.  **精度保持**：在追求极致性能的同时，INT8量化后的模型关键指标（如F1分数）的下降必须控制在1%以内。
4.  **系统集成**：设计一套稳定可靠的通信协议，实现RK3588与卫星主控计算机（OBC）之间通过CAN总线的遥测上报（如心跳、告警）和遥控指令（如启停、复位）交互。

### Action (行动)

为了完成这个极具挑战性的任务，我采取了一系列深入的技术**行动**：

1.  **模型转换与算子适配**
    *   **遇到的问题**：在将模型从PyTorch导出为ONNX，再尝试用RKNN Toolkit转换为RKNN格式时，转换流程因一个`LayerNorm`算子的特定参数不被NPU底层驱动支持而中断。
    *   **我的思考与解决**：我没有要求算法团队重构模型（这会耗费大量时间），而是深入研究了`LayerNorm`的数学原理。我发现可以将其**等效拆解**为一系列RKNN支持的基础算子（如`Mean`, `Sub`, `Pow`, `Div`, `Add`, `Mul`）。我编写了一个Python脚本，在ONNX计算图层面自动进行这种**算子替换**，成功绕过了工具链的限制，打通了模型转换的第一步。

2.  **精度无损的INT8量化**
    *   **遇到的问题**：初次使用官方工具进行标准的“后训练量化”（Post-Training Quantization），模型的F1分数从99.5%**断崖式下跌到了92%**，完全不满足项目要求。
    *   **我的思考与解决**：我判断，简单的量化方式对模型中某些层的数据分布特别敏感。为此，我设计并实施了一套**数据驱动的混合精度量化方案**：
        *   **敏感层分析**：我编写了一个逐层分析脚本，将一个精心挑选的、包含多种攻击样本的**校准数据集**输入给原始FP32模型和INT8模型，并对比每一层输出的余弦相似度。通过该方法，我精确定位到模型的**初始Embedding层和最终的分类层**对量化误差最为敏感。
        *   **混合精度策略**：在掌握了敏感层信息后，我利用RKNN Toolkit的高级功能，配置了一个**混合精度量化策略**：对最敏感的头尾两层**保持FP16精度**，而对中间计算量巨大的Transformer块则**应用INT8量化**。
        *   这个方案最终在几乎不牺牲性能的前提下，将模型的F1分数**恢复到了99.1%**，成功解决了精度下降的难题。

3.  **高可靠的CAN总线通信协议设计**
    *   **遇到的问题**：CAN总线本身是一种简单的广播协议，不保证消息送达，也容易受到总线风暴的影响。我们需要在其之上构建一套可靠的“应用层”协议。
    *   **我的思考与解决**：我设计了一套包含心跳、指令确认和高优先级告警的通信规约：
        *   **心跳帧 (ID: `0x700`)**: RK3588每秒发送一次，数据场第一字节为载荷状态码（如`0x00`=正常, `0x01`=正在初始化, `0xFF`=故障），OBC据此监控载荷健康。
        *   **指令/应答帧 (ID: `0x600`/`0x601`)**: OBC下发指令，如`ID=0x600, Data=[0x01]`代表“开始检测”。RK3588收到后，必须在100ms内回复`ID=0x601, Data=[0x01]`作为ACK。若OBC超时未收到ACK，则会重发指令，实现了**指令必达**。
        *   **威胁告警帧 (ID: `0x1A0`)**: 这是**最高优先级**的报文。一旦NIDS检测到威胁，立即发送此帧，数据场包含威胁类型、时间戳和攻击源等关键信息，确保OBC能第一时间采取反制措施。

### Result (成果)

通过上述一系列技术攻关，我成功地将一个实验室里的AI模型，转化为了一个能在太空中稳定运行的、高性能的嵌入式入侵检测载荷：
1.  **极致的性能与能效**：最终部署的混合精度RKNN模型在RK3588 NPU上，处理一个网络数据包的**平均推理延迟仅为15ms**，远低于20ms的设计指标。相较于在ARM CPU上运行的FP32模型，**性能提升超过20倍**，而载荷平均功耗稳定在**8W**左右，完全满足星上严苛的能效比要求。
2.  **高精度的威胁检测**：量化后的模型F1分数高达**99.1%**，确保了在轨检测的准确率和低误报率，达到了国内领先水平。
3.  **任务交付与团队协作**：我设计的CAN通信方案一次性通过了与航天院的联调测试，为后续的整星集成铺平了道路。该载荷的成功研制，使我司成为该卫星型号网络安全方向的核心供应商。
4.  **个人成长**：该项目使我获得了在**资源受限环境下进行AI模型深度优化**的宝贵经验，并深入理解了嵌入式系统开发与高可靠性系统设计的核心要素。
