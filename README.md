# 仓库管理系统 (WMS) 项目

## 1. 项目概述

本项目是一个使用 Java 和 Spring Boot 框架构建的综合性仓库管理系统 (WMS)。它旨在管理一个复杂的仓库环境，该环境既包含手动操作，也包含高度的自动化。该系统处理标准的 WMS 功能，如入库和出库订单、库存管理和库位管理，同时还与各种自动化硬件集成。

系统的主要功能包括：
-   物料、库位、托盘和设备的主数据管理。
-   入库（接收）和出库（发货）订单的端到端处理。
-   实时库存跟踪，包括数量、批次和位置。
-   与多个专业自动化仓库区域的集成。
-   用于仪表板和报告的数据分析和统计模块。
-   用于管理用户权限的基于角色的访问控制系统。

## 2. 系统架构

该应用程序构建在现代 Java 技术栈上，并采用了几个关键的架构模式。

### a. 核心应用框架
- **后端:** Spring Boot
- **API 风格:** RESTful API (使用 `@RestController`)
- **数据访问:** 使用 MyBatis-Plus 进行数据库交互，提供了一个功能强大且灵活的数据映射框架。
- **数据库:** 主要配置的数据库是 **Kingbase8**（人大金仓），同时提供了 MySQL 和 SQL Server 的配置选项。

### b. WCS 集成与任务处理
WMS 与多个管理自动化硬件的外部仓库控制系统 (WCS) 进行通信。这种通信的架构是一种 **后台轮询机制**。

- **轮询线程:** 一系列后台线程（例如 `ThreadP`、`ThreadB`、`ThreadD`）持续运行。
- **任务分派:** 每个线程负责一个特定的仓库区域。它轮询其对应的任务表（例如 `t_task_p`）以查找状态为“待执行”的新任务。
- **API 通信:** 当找到待处理任务时，线程通过 REST API 调用将命令发送到相应的 WCS。这些外部 API 的 URL 在 `application.properties` 中配置。
- **主 WCS:** 一个中央“Z” WCS (`TaskZController`) 似乎充当主控制器，协调高级别任务并接收状态更新，然后将其委托给相应的内部服务。

### c. 外部系统集成
- **上游系统:** WMS 与一个更高级别的系统（很可能是 ERP）集成。`UpSystemController` 负责将已完成的入库和出库订单报告回该系统。
- **硬件 API:** 系统与各种硬件集成，每种硬件都有自己的 API：
  - **AGV/CTU 系统:** 用于自动导引车和容器传输单元。
  - **ASRS 系统:** 用于 P、B、D 和 X 仓库中的自动化存储和检索。
  - **LED 屏幕:** 与 OnBon LED 屏幕的底层集成，用于显示信息。
  - **PLC:** 与回转库（“H”库）的 PLC 直接通信。

## 3. 核心业务流程

### a. 入库流程
1.  **订单创建:** 在系统中创建一个 `InOrder`（入库单），可以手动创建或通过上游系统的 API 调用创建。添加 `InOrderDetail` 行以指定预期的物料和数量。
2.  **货物接收:** 货物到达时，用户（可能使用 PDA）调用 `/Inventory/AddReceiveMaterial` 端点。这是一个关键的事务性步骤，它会：
    -   增加 `InOrderDetail` 上的 `actual_count`（实际接收数量）。
    -   为接收到的物料、批次和托盘创建或更新 `Inventory` 记录。
    -   将 `InOrder` 状态更新为“收货中”或“已完成”。
3.  **上架任务生成:** 在适当的任务表（例如 `TaskP`、`TaskB`）中创建一个上架任务，指定托盘及其目标位置。
4.  **自动上架:** 相应的后台线程（`ThreadP`、`ThreadB` 等）获取待处理的任务，并向 WCS 发送命令以执行物理移动。

### b. 出库流程
1.  **订单创建:** 创建一个 `OutOrder` 及其 `OutOrderDetail` 行。
2.  **分配 (拣货):** 用户通过调用 `/OutPick/OrderPick` 端点启动拣货流程。这个关键步骤会：
    -   检查可用库存。
    -   创建 `OutPick` 记录，这些是用于从特定库存位置拣选特定数量物料的具体任务。
    -   通过增加 `frozen_count` 来冻结 `Inventory` 表中的已分配数量。
3.  **任务生成:** 通过调用像 `/TaskP/Pick2TaskP` 或 `/TaskB/Pick2TaskB` 这样的端点，将 `OutPick` 记录转换为仓库任务。
4.  **自动拣货:** 后台线程将这些任务分派给 WCS，以检索所需的托盘/料箱并将其运送到工作站。
5.  **工作站交互:** 在工作站，系统通过电子标签 (`TaskZController`) 管理用户交互，以指导从源料箱到目标订单箱的拣货过程。
6.  **发货:** 订单完全拣选后，一个 `Checkout` 流程会更新 `OutOrderDetail` 上的最终发货数量。
7.  **上游报告:** 已完成的订单通过 `UpSystemController` 报告回上游系统。

## 4. 关键模块 (包)

- **`controller`**: 包含定义应用程序 API 端点的 Spring REST 控制器。
- **`service`**: 包含业务逻辑层。虽然许多服务是简单的包装器，但关键逻辑位于 `CheckService`、`CheckDetailService` 和 `StatisticService` 中。
- **`entity`**: 包含数据模型，包括数据库映射实体和用于 API 通信的 DTO。
- **`mapper`**: 包含用于数据库查询的 MyBatis 映射器接口和 XML 文件。
- **`wcs`**: 包含驱动与自动化系统通信的后台轮询线程。
- **`led`**: 包含用于 LED 显示屏的底层集成。
- **`statistic`**: 包含用于数据分析和仪表板功能的控制器和服务。
- **`config`**: 包含 Spring Boot 和 MyBatis 配置类。

## 5. 构建和运行

(构建和运行说明占位符)

要构建和运行此应用程序，您需要：
- Java JDK (版本在 `pom.xml` 中指定)
- Apache Maven
- 对具有所需模式的正在运行的 Kingbase8 数据库实例的访问权限。

**构建步骤:**
```bash
# 从仓库的根目录
mvn clean install
```

**运行步骤:**
1.  确保 `application.properties` 文件具有适合您环境的正确数据库和外部 API URL。
2.  使用 Spring Boot Maven 插件运行应用程序：
```bash
mvn spring-boot:run
```
3.  应用程序将在 `http://127.0.0.1:9999` 上可用。
