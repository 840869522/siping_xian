# WCS 和后台任务包

本文档描述了 `com.example.wmsmp.wcs` 和 `com.htsn.wcs` 包中的类。这些包负责仓库任务的后台处理以及与各种仓库控制系统 (WCS) 的通信。

## WCS 任务轮询 (`com.example.wmsmp.wcs`)

这个包揭示了应用程序的一个核心架构模式：**后台任务轮询**。应用程序不是等待外部触发，而是运行一系列后台线程，这些线程持续轮询数据库以查找要发送到自动化硬件系统的新任务。

此包中的每个 `Thread` 类都对应一个特定的自动化仓库区域：

- **`ThreadP`**: 管理“P库”（托盘库）的任务。
- **`ThreadB`**: 管理“B库”（料箱库）的任务。
- **`ThreadD`**: 管理“D库”（大件库）的任务。
- **`ThreadX`**: 管理“X库”（箱组库）的任务。
- **`ThreadSort`**: 管理“分拣机”的任务。

### 每个线程的通用逻辑

每个线程（`ThreadP`、`ThreadB` 等）都遵循相同的基本逻辑：

1.  **无限循环:** 在一个 `while(true)` 循环中运行。
2.  **休眠:** 在每个循环开始时暂停几秒钟 (`Thread.sleep(3000)`)。
3.  **查询待处理任务:** 它查询其对应的任务表（例如，`t_task_p` for `ThreadP`）中任何状态为“待执行”的记录。
4.  **限制已分派任务:** 它经常检查已经处于“已下发”状态的任务数量，以避免压垮 WCS。如果活动任务数量太多，它会跳过当前循环。
5.  **分派任务:** 如果找到一个待处理任务且活动任务队列未满，它会取第一个待处理任务。
6.  **调用 WCS API:** 它构造适当的请求对象（例如，一个 `ZTask` 对象）并将其发送到相应的 WCS API 端点（例如，用于 `ThreadP` 和 `ThreadB` 的“Z”主 WCS）。
7.  **更新任务状态:** 根据来自 WCS 的响应，它将 WMS 数据库中任务的状态更新为“已下发”或错误状态。

## 独立的 WCS 应用程序 (`com.htsn.wcs`)

这个包似乎包含一个可以作为 WCS 运行的独立 Java 应用程序的源代码。

- **`main.WcsMain`**: 这个类有一个 `public static void main` 方法，使其成为一个可执行的应用程序。其逻辑包括：
  - 读取 `application.properties` 文件。
  - 初始化数据库连接（尽管代码被注释掉了）。
  - 启动一个新线程来 `loopReadDB()`。
- **`common.ConfigUtil` / `common.StringUtil`**: 这些分别是用于读取属性文件和执行字符串操作的工具类。

**架构启示:** 这个包的存在表明，该系统最初可能被设计为两个独立的应用程序（一个 WMS 和一个 WCS），它们通过数据库进行通信。然而，`com.example.wmsmp.wcs` 包中轮询线程的存在表明，该逻辑很可能已直接集成到主 WMS Spring Boot 应用程序中，而这个 `com.htsn.wcs` 包可能已被弃用或是先前设计的残留物。
